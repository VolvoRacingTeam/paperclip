# Paperclip ES256 JWKS

**Task #26** — 2026-04-24
**Status:** implementert, venter på Cloudflare Access bypass for `.well-known/*`

## Hvorfor

Kundeoversikt Sprint 35 (kickoff 2026-04-28) skal verifisere agent-JWT
signert av Paperclip. Task #24-designet valgte **ES256** (ECDSA P-256)
fremfor HS256 fordi Kundeoversikt-backend da ikke trenger å dele noen
hemmelighet med Paperclip — kun offentlig nøkkel hentes fra JWKS og caches.

Eksisterende `agent-auth-jwt.ts` (HS256) er *intern* Paperclip-auth for
agents som snakker med Paperclip-API. Den er uendret. Den nye modulen
`agent-jwt-es256.ts` brukes kun for tokens som eksporteres ut av Paperclip
til tredjepart-API.

## Endepunkt

`GET https://paperclip.nullmas.no/.well-known/jwks.json` (offentlig, ingen auth)

Eksempel-svar:
```json
{
  "keys": [
    {
      "kty": "EC",
      "crv": "P-256",
      "x": "...",
      "y": "...",
      "use": "sig",
      "alg": "ES256",
      "kid": "paperclip-2026-04"
    }
  ]
}
```

Headers:
- `Content-Type: application/json`
- `Cache-Control: public, max-age=3600`

## Nøkkellagring

- Privat PEM: `/paperclip/secrets/paperclip-es256-private.pem`
  (mode 0600, mount i paperclip-container via `paperclip-data` Docker-volum).
- Offentlig PEM: `/paperclip/secrets/paperclip-es256-public.pem` (mode 0644).
- Ingen nøkkel skal committes til git. `.gitignore` håndterer ikke dette
  siden `/paperclip/secrets/` er utenfor repoet — men pass på at nøkler
  aldri kopieres inn i repo-rooten.

Nøkkelen kan alternativt lastes fra environment:
- `PAPERCLIP_JWT_PRIVATE_KEY_PEM` (full PEM, real eller `\n`-escaped)
- `PAPERCLIP_JWT_PRIVATE_KEY_PATH` (absolutt sti)

Fallback-rekkefølge: inline PEM → custom path → default
`/paperclip/secrets/paperclip-es256-private.pem`.

## Tuning-env

| Variabel                       | Default                         |
|--------------------------------|---------------------------------|
| `PAPERCLIP_JWT_KID`            | `paperclip-2026-04`             |
| `PAPERCLIP_JWT_ISSUER`         | `https://paperclip.nullmas.no`  |
| `PAPERCLIP_JWT_AUDIENCE`       | `kundeoversikt.no`              |
| `PAPERCLIP_JWT_TTL_SECONDS`    | `600` (10 min)                  |

## Kodepunkter

- `server/src/agent-jwt-es256.ts` — nøkkel-lasting, JWK-eksport, `signAgentEs256Jwt`.
- `server/src/routes/well-known.ts` — `GET /.well-known/jwks.json`.
- `server/src/app.ts` — mounter ruta direkte på `app` (ikke under `/api`).
- `server/src/__tests__/agent-jwt-es256.test.ts` — JWT-roundtrip mot lokal JWKS.

## Nøkkelrotasjon

1. Generer nytt nøkkelpar med ny `kid`:
   ```bash
   docker exec paperclip sh -c 'cd /paperclip/secrets \
     && openssl ecparam -genkey -name prime256v1 -noout -out paperclip-es256-private-2026-05.pem \
     && openssl ec -in paperclip-es256-private-2026-05.pem -pubout -out paperclip-es256-public-2026-05.pem \
     && chmod 600 paperclip-es256-private-2026-05.pem'
   ```
2. **Publiser både gammel og ny public key i JWKS** (minst 1× `Cache-Control: max-age` = 1t).
   Dette krever en liten utvidelse av `agent-jwt-es256.ts` til å lese flere
   nøkler (MVP eksponerer én). Planlagt for neste rotasjon.
3. Skru om signering til ny `kid` ved å sette `PAPERCLIP_JWT_KID` og
   `PAPERCLIP_JWT_PRIVATE_KEY_PATH` til den nye fila og restarte containeren.
4. Fjern gammel public key fra JWKS etter at alle konsumenter har rotert
   cachen (minst 1h etter trinn 3).

## Cloudflare Access

Tunnel-ingress for `paperclip.nullmas.no` er konfigurert, men Access-policyen
("Kun Tore") må ha eksplisitt **bypass / public** for stien
`/.well-known/*` slik at Kundeoversikt-backend kan hente JWKS uten
Cloudflare-login.

Per 2026-04-24 er dette *ikke* endret (jeg vil ikke touche Access-policyer
uten din godkjenning). Handlingsliste:

- Gå til Cloudflare Zero Trust → Access → Applications
- Finn application for `paperclip.nullmas.no`
- Legg til en bypass-regel eller dediker en sekundær app for pathen
  `/.well-known/jwks.json` med policy = "Bypass (everyone)"

Verifiser etter endring:
```bash
curl -sv https://paperclip.nullmas.no/.well-known/jwks.json | jq .
# Skal returnere 200 + valid JWKS uten å bli redirected til Cloudflare-login.
```

## Monitoring

- Helsecheck: hente JWKS + validere at `keys[0].kid` matcher forventet.
- Legg til i alerting (son97-alerting eller equivalent):
  ```
  curl -fsS https://paperclip.nullmas.no/.well-known/jwks.json | jq -e '.keys|length>0'
  ```

## Ikke-mål (Task #26)

- Faktisk sende Bearer JWT på utgående kall til Kundeoversikt er *ikke*
  del av Task #26. Dagens `kundeoversikt-tools.ts` bruker statisk
  `AGENT_API_KEY`. Migrering til JWT-basert auth skjer i Sprint 35
  når Kundeoversikt-backend har JWKS-verifikatoren på plass.
- Multi-kid JWKS (liste over nøkler for zero-downtime rotasjon) er planlagt
  men ikke implementert (se rotasjon-steg 2).
